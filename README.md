# 오운 · 오늘의 움직임

React + TypeScript + Vite로 만든 한국어 운동 기록 웹앱입니다. PC와 모바일에서 사용할 수 있습니다. 회원가입, API 키, 서버나 데이터베이스 설정 없이 시작할 수 있습니다.

## 처음 실행하기

1. **Node.js 22.12 이상**을 설치하세요. 개발 환경에서는 Node.js 24로 확인했습니다.
2. 터미널에서 이 프로젝트 폴더를 여세요.
3. 아래 명령을 한 줄씩 실행하세요.

```bash
npm ci
npm run dev
```

터미널에 표시되는 주소를 브라우저로 열면 됩니다. 종료할 때는 터미널에서 `Ctrl + C`를 누르세요.

클라우드 환경에서 npm 캐시 권한 오류가 나면 설치 명령을 아래처럼 실행하세요.

```bash
npm ci --cache /tmp/gym-app-npm-cache
```

## 이렇게 사용하세요

### 1. 달력에서 날짜 선택

- 상단의 월 선택 또는 화살표로 달을 바꾸고, 날짜를 누르세요.
- 달력에는 운동 계획, 진행, 세션 완료 상태와 부위(가슴·등·어깨·하체 등)가 표시됩니다. 부위의 테두리는 계획, 채운 색은 한 세트 이상 운동한 부위를 뜻합니다.
- 위쪽에는 해당 월의 운동한 날, 완료 세션, 완료 세트 수가 표시됩니다.
- **날짜를 약 0.65초간 길게 누르면 하루 루틴 전체가 복사됩니다.** PC에서는 기록 상단의 복사 아이콘도 사용할 수 있습니다.
- 다른 날짜를 선택한 뒤 **붙여넣기**를 누르세요. 기존 계획이 있으면 교체 전 확인합니다.
- 복사하는 것은 운동 순서·세트·무게·횟수·시간·휴식 설정입니다. 완료 표시·운동시간·메모는 복사하지 않습니다. 복사 보관함은 현재 화면에서만 유지됩니다.

### 2. 운동과 루틴 구성

- **운동 추가하기**에서 이름 검색, 신체 부위, 도구로 운동을 찾으세요.
- 가슴·등·어깨·하체·팔·코어·유산소·전신의 기본 운동 98종목을 제공합니다.
- 맨몸·덤벨·바벨 및 머신·유산소 운동을 포함합니다. 기본 목록에 없는 운동은 **직접 추가**에서 이름·분류·도구·기록 방식을 정하세요.
- 무게 × 횟수 또는 시간(초)을 세트마다 입력합니다. 예를 들어 20분 걷기는 **1200초**, 1분 플랭크는 **60초**입니다.
- 무게 칸의 선택 메뉴에서 **중량 kg / 맨몸**을 고르세요. 맨몸 세트는 횟수만 기록하고 중량 볼륨에서 제외합니다. 덤벨은 한 손 무게, 좌우 운동은 한쪽 횟수를 권장하며 양손·좌우를 자동으로 두 배 계산하지 않습니다.
- 무게·횟수·시간·휴식 입력이 **0일 때 칸을 누르면 빈칸**이 되어 바로 입력할 수 있습니다. 빈 상태로 다른 곳을 누르면 0으로 돌아오며, 저장된 숫자 데이터는 기존 기록과 호환됩니다.
- 세트를 추가·삭제하고 운동의 위아래 화살표로 순서를 바꿀 수 있습니다.
- **루틴 저장**으로 하루 계획을 이름과 함께 최대 **10개** 저장하고 언제든 불러오세요. 내 루틴에서 삭제할 수 있습니다. 전신·덤벨 상체·유산소 예시 루틴도 제공합니다.
- 이미 시작한 기록에는 붙여넣기·불러오기로 덮어쓸 수 없습니다. 다른 날짜를 선택하거나 진행 기록을 초기화하세요.

### 3. 전체 운동, 세트 기록과 휴식

1. 날짜에 운동 계획을 구성한 뒤 **전체 운동 시작**을 누르세요. 이 시점부터 전체 운동시간을 측정합니다.
2. 일반 운동은 세트를 마친 후 해당 세트의 **휴식**을 누르세요. 세트 완료를 기록하고 휴식 타이머를 시작합니다.
3. 휴식 종료 시 화면 알림과 **종소리 3번**으로 알려줍니다. **휴식 종료**로 즉시 끝내거나 **+15초**로 연장할 수 있습니다.
4. 모든 운동을 마쳤으면 **전체 운동 종료**를 누르세요. 시작 버튼부터 종료 버튼을 누른 시각까지 휴식·대기를 포함한 시간을 저장합니다. 마지막 세트를 마쳐도 자동 종료하지 않습니다.

- 중간에 종료할 수도 있습니다. 남은 세트는 미완료로 보관하며 종료 전 확인창을 표시합니다.
- 시간 종목의 입력값은 목표 시간(초)입니다. 별도 세트 카운트다운은 없고, 목표만큼 운동한 뒤 휴식을 누릅니다.
- 완료 표시를 잘못 누르면 해당 세트의 체크 버튼을 다시 눌러 취소하세요. 이미 종료한 세션은 수정으로부터 보호합니다.
- 진행 중인 세션은 한 번에 하나입니다. 새로고침하면 진행 중인 날짜로 돌아와 이어서 기록합니다. 운동을 오래 열어 둔 시간도 포함되므로 끝나면 전체 운동 종료를 누르세요.
- 종목별 휴식시간 또는 설정의 기본 휴식을 조정할 수 있습니다. **0초는 휴식 없음**입니다.
- 설정에서 **종소리 3번 테스트**로 기기 볼륨을 확인하세요. 음소거도 가능합니다.
- 화면 잠금·앱 종료·백그라운드에서는 브라우저 정책 때문에 알림이 늦거나 소리가 나지 않을 수 있습니다. 돌아오면 실제 종료 시각을 기준으로 갱신합니다. 앱을 완전히 닫은 동안에는 종소리가 울리지 않습니다.
- **진행 기록 초기화**는 세트 완료 표시와 운동시간을 지우고 계획·슈퍼세트 구성·메모는 유지합니다. 하루 삭제는 메모까지 삭제합니다.

#### 두 운동을 슈퍼세트로 진행하기

- **전체 운동 시작 전**, 운동 제목 옆 **연결 아이콘(슈퍼세트 지정)**을 누른 뒤 짝 운동을 선택하세요.
- 두 운동을 붙여 배치하고, 세트 수가 다르면 많은 쪽에 맞춰 부족한 세트를 추가합니다. 휴식은 처음 선택한 운동의 시간을 공유합니다.
- 예: 푸시업 1세트 → 푸시업의 **완료** → 덤벨 로우 1세트 → 덤벨 로우의 **휴식** → 휴식 후 2라운드.
- 어떤 종목부터 해도 됩니다. 첫 종목에는 **완료**, 같은 라운드의 나머지 종목에는 **휴식** 버튼이 표시됩니다. 두 종목을 모두 기록하기 전에는 휴식을 시작하지 않습니다.
- 이전 라운드의 두 종목을 마쳐야 다음 라운드를 기록할 수 있습니다. 이후 라운드가 기록된 경우 앞 라운드를 취소하려면 이후 라운드부터 취소하세요.
- 슈퍼세트에서 세트 추가·삭제는 두 운동에 함께 적용되며, 휴식 설정도 공유됩니다. 순서 이동은 두 운동이 함께 움직입니다.
- 운동 시작 전 **해제**로 연결을 풀 수 있습니다. 운동이 시작된 뒤에는 연결·해제가 잠기며 필요하면 진행 기록을 초기화하세요.
- 루틴 저장·불러오기, 날짜 간 복사·붙여넣기, JSON 백업·복원에 슈퍼세트 구성이 함께 보관됩니다. 기존 버전 기록과 백업도 읽을 수 있습니다.

### 4. 기록 확인과 내보내기

- 세트 옆 **지난 기록**에 같은 운동의 이전 날짜 완료 세트 값이 표시됩니다.
- 하루 메모에 컨디션이나 다음 운동의 목표를 적어 두세요.
- 기록 상단의 문서 아이콘에서 **텍스트 복사** 또는 **TXT 내려받기**를 사용하세요. 운동시간, 종목, 완료·미완료 세트, 무게·횟수·시간, 휴식 설정과 메모를 포함합니다.

### 5. 기록 보관과 백업

- 날짜별 기록, 커스텀 운동, 저장 루틴, 설정은 **현재 브라우저의 localStorage**에 자동 저장합니다.
- 같은 기기라도 브라우저나 사이트 주소·포트가 달라지면 저장 공간이 달라집니다. 모바일·PC 간 자동 동기화는 없습니다.
- 시크릿 모드 종료, 브라우저 데이터 삭제, 기기 변경에 대비해 **설정 → JSON 백업**을 정기적으로 사용하세요.
- **백업 복원**은 형식과 용량(최대 5MB)을 검사한 뒤 전체 기록을 교체합니다. 복원 전 현재 데이터를 백업하세요. 진행 중 세션은 보존하되 휴식 알림은 초기화합니다.
- 저장 실패 시 화면에 경고가 표시됩니다. 이 경우 화면을 닫기 전에 백업을 내려받으세요. 손상된 기존 데이터는 자동으로 덮어쓰지 않습니다.

## 개발 명령

```bash
npm run typecheck  # TypeScript 오류 검사
npm run build      # 타입 검사 + dist/에 배포용 파일 생성
npm run preview    # 빌드 결과 확인 (build 후)
```

### 자동 테스트

일반 개발 PC에서는 처음 한 번 테스트 브라우저를 설치합니다.

```bash
npx playwright install chromium
npm test
```

설치된 Chromium을 직접 사용하려면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`를 지정하세요. 클라우드에서는 브라우저 다운로드 도메인이 제한될 수 있습니다. 이 환경에서는 npm으로 받은 `@sparticuz/chromium`의 실행 파일을 사용해 실제 브라우저 테스트를 수행했습니다.

```bash
# 이 클라우드의 현재 Chromium 실행 파일을 사용하는 예시
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/tmp/chromium XDG_CACHE_HOME=/tmp/gym-browser-cache npm test
```

테스트는 별도 포트 5174에서 앱을 시작합니다. 데이터 계산·백업 검증, 길게 누르기 복사·붙여넣기, 루틴 저장 제한, 커스텀 운동, 세션 진행·휴식 종소리 3회 생성·내보내기, 새로고침 복원, 부분 완료, 0 입력·맨몸 선택·슈퍼세트 라운드·기존 백업 호환성과 360/390/768/1440px 레이아웃을 검증합니다. 테스트 브라우저에서 실제 스피커의 볼륨까지 확인하지는 않습니다.

## 파일 구성

```text
src/
  App.tsx                        전체 화면과 운동 진행 흐름
  components/Calendar.tsx         월간 달력·부위 표시·길게 누르기
  components/NumberInput.tsx      0 입력 시 빈칸으로 전환하는 공통 입력
  components/WorkoutCard.tsx      맨몸·세트·슈퍼세트 편집과 휴식
  components/ExerciseLibrary.tsx  운동 검색·분류·커스텀 추가
  components/Modal.tsx            공통 대화상자
  lib/catalog.ts                 기본 운동 98종목
  lib/workout.ts                 날짜·세트·저장 데이터 검증·내보내기
  types/workout.ts                운동 기록 데이터 구조
  main.tsx                       앱 진입점
  styles.css                     화면 및 반응형 스타일
 tests/workout.spec.ts            계산 및 실제 브라우저 시나리오 테스트
 playwright.config.ts            테스트 실행 설정
```

기능 설계는 Strong·Hevy 등 운동 기록 앱에서 널리 쓰이는 루틴 재사용, 세트별 기록, 휴식 타이머, 이전 기록 확인 흐름을 참고했습니다. 현재 환경에서는 공식 사이트 접근이 차단되어 최신 제품 화면을 직접 비교하지 않았습니다.

## 문제 해결

- `npm`을 찾을 수 없으면 Node.js 설치 후 터미널을 다시 여세요.
- 개발 포트가 사용 중이면 Vite가 안내한 실제 포트를 확인하세요.
- 패키지 문제가 있으면 프로젝트 폴더에서 `npm ci`를 다시 실행하세요.
- 소리가 나지 않으면 설정에서 소리 테스트를 누르고 기기 볼륨 및 브라우저 자동재생 정책을 확인하세요.
- 기록이 안 보이면 이전에 사용한 브라우저·주소·포트인지 확인하고, JSON 백업이 있다면 복원하세요.

## 공개 웹주소로 배포하기

현재 배포용 빌드는 준비되어 있습니다. 공개 주소 발급에는 Netlify 또는 Vercel 계정과 배포 권한이 필요합니다. 이 클라우드의 개발 환경 게시와 웹앱 배포는 별개입니다.

### 가장 간단한 방법: Netlify 파일 업로드

1. `npm run build`로 `dist` 폴더를 만듭니다.
2. https://app.netlify.com/drop 에서 Netlify 계정으로 로그인합니다.
3. `dist` 폴더 또는 준비된 배포 ZIP을 업로드합니다. ZIP을 받지 않는 화면이면 압축을 풀어 `index.html`이 들어 있는 폴더를 올리세요.
4. Netlify가 제공하는 `https://사이트이름.netlify.app` 주소로 접속합니다.

이 작업에서 만든 ZIP은 `/workspace/gym-app-deploy.zip`입니다. 앱의 실행 파일만 포함하며 소스 코드, 개발 패키지, 운동 기록은 포함하지 않습니다. 앱을 수정하면 다시 빌드해 새 배포 파일을 업로드해야 합니다.

### GitHub 저장소 연결로 자동 배포

소스 코드가 GitHub에 올라간 뒤 Netlify 또는 Vercel에서 저장소를 연결할 수 있습니다. 빌드 명령은 `npm run build`, 결과 폴더는 `dist`, Node.js는 24로 설정합니다. `netlify.toml`과 `vercel.json`에 해당 설정을 포함했습니다.

배포 후 첫 접속에서는 개발 중의 기록이 보이지 않는 것이 정상입니다. 사이트 주소가 달라지면 브라우저 저장 공간도 달라집니다. 기존 기록을 옮기려면 기존 화면에서 JSON 백업을 내려받아 새 주소의 설정에서 복원하세요.
